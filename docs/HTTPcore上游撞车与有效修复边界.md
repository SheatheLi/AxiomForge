# HTTPcore #1113 与 AxiomForge 原生候选补丁的竞争撞车

实际 HTTPX #3782 原生复现与本地 HTTPcore 1.0.9 候选补丁证据保留。**但修复原创性必须降级**：上游第三方 PR [httpcore#1113](https://github.com/encode/httpcore/pull/1113) 已于 2026-09-16 提出“清理失败后恢复 `_closed` 状态，允许外部重试”的基本思想，并公开报告 8 个新增参数化回归、完整上游测试及 20 轮 HTTPX 集成。当前 AxiomForge 的 rearm 候选与其在机制层面高度重合，不能声称独创上游修复或已在其强基线上取胜。

本轮保持对真实服务的差分测试与修复边界验证；多个候选（rearm、defer、single-flight）只在指定 asyncio/HTTP1.1 四轮双次取消中获得零连接残留。简化有限状态模型指出：如果清理始终持续被取消且没有剩余重试预算，即使延迟提交仍可能失效。这不是通用没有资源泄漏的证明。

下一步要找到**能够独立提高 AxiomForge 通用技术能力**的问题族，如跨第三方实现的资源责任/状态机诊断、系统化取消交错缩减或未见对象/历史版本的自动 Oracle；验证其在冻结的外部项目上超越人工定位、已有上游检测和成熟可靠性工具的特定价值。若没有不能宣传“自动修复 8 种真实外部 Issue”。
